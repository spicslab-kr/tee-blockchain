**The two lines whose result is not the expected one, and why.** Both are this network aborting SSH connections, not
the checks:

- `arch-measurement-compare.sh`, `x86-two-machines`, `error`: the Auditor built fine (its PCRs are in the log), but
  fetching its `measurements.json` printed a bare `scp: Connection closed`, which `net_retry` did not know and did not
  retry. The file was fetched again on its own and was identical to the Vendor's; that comparison is the hand-written
  line (`script` says so). `net_retry` now retries that message (`test(e2e): retry an scp whose connection closed`).
- `responder-check.sh`, the correct responder, `refused`: its SSH failed three times with `kex_exchange_identification:
  Connection reset by peer` (retried, as `net_retry` does), the same step and the same failure as on 2026-11-12. The
  whole script was run again with `SSH_TRIES=5` and passed; the same three resets happened and the fourth attempt got
  through.
